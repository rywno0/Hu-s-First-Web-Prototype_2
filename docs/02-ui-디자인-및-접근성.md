# 02. UI 디자인 및 접근성 지침

## 참고 이미지에서 가져올 시각 방향
- 전체 화면은 깊은 검정 배경, 큰 흰색 타이포그래피, 넉넉한 여백으로 구성한다.
- 형광 라임(#B7F21A 근처)은 작은 포인트, 상태 강조, 장식 그래픽에 제한적으로 쓴다. 본문 텍스트를 라임색으로 길게 쓰지 않는다.
- 이미지의 중앙 점 입자 원형 그래픽은 장식 레이어로 구현할 수 있다. 캔버스/ CSS로 가볍게 만들고, 분석 결과나 입력 조작을 가리지 않는다. 모션은 기본적으로 느리고 미세하게 하며 `prefers-reduced-motion`에서 중지한다.
- 상단에는 텍스트 워드마크와 간결한 탐색/서비스 표기를 둔다. 실제 회사명, 수상 배지, 존재하지 않는 링크나 허위 수상 표시를 복제하지 않는다.
- 히어로 제목은 짧고 강한 문구로, 입력 패널은 그 아래 명확히 배치한다. 화면 밖으로 잘리는 큰 제목 연출은 모바일에서 금지한다.

## 화면 구성
1. 상단 브랜드 영역: 임시 서비스명과 “텍스트 감성 분석” 설명.
2. 히어로 영역: 큰 제목(예: “마음의 결을 읽다”), 짧은 소개 문장.
3. 입력 카드: 설명 레이블이 있는 textarea, 글자 수/최대 길이, 분석 버튼, 전송 안내.
4. 결과 영역: 초기에는 숨기거나 예시 결과를 실제 결과처럼 보이지 않게 명확히 구분. 완료 후 감성 라벨, 신뢰도 숫자/막대, 분석 근거 표시.
5. 하단 참고 문구: AI 결과의 참고용 성격과 입력 저장 여부 안내.

## 인터랙션/접근성
- 버튼 이름은 “감성 분석하기”로 고정한다. 분석 중에는 비활성화하고 “분석 중…” 상태를 보여준다.
- 결과/오류 갱신 컨테이너에 `aria-live="polite"`와 적절한 역할을 적용한다. 오류는 색만으로 전달하지 않는다.
- 모든 입력에는 명시적 label이 있고 포커스 표시가 보인다. 색 대비는 일반 텍스트 WCAG AA 수준을 목표로 한다.
- 라벨은 아이콘/색상뿐 아니라 텍스트로 표시한다. 긍정/부정/중립 색상은 보조 신호로만 쓴다.
- 좁은 화면에서는 단일 열, 충분한 터치 영역, 화면 내 줄바꿈을 사용한다. 가로 스크롤이 생기지 않도록 한다.
- 오류 후 입력을 지우지 않는다. 성공/오류 상태가 이전 결과와 혼동되지 않게 결과 영역을 갱신한다.

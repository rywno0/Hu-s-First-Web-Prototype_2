# 03. 기능 구현 및 사용자 흐름

## 입력 조건
- 앞뒤 공백을 제거한 값으로 분석한다. 빈 값이면 서버 요청 없이 입력 영역에 오류를 표시한다.
- 최대 길이는 2,000 Unicode 코드 포인트다. 초과 시 전송을 막고 허용 길이를 안내한다.
- 입력 언어는 제한하지 않지만 사용자 인터페이스와 기본 안내는 한국어다. 이모지/한글/영문이 섞여도 글자 수 계산이 깨지지 않아야 한다.

## 상태 모델
- `idle`: 입력 가능, 결과 없음 또는 마지막 결과 표시.
- `loading`: 제출 버튼 비활성, 진행 안내.
- `success`: 새 결과의 감성 라벨/신뢰도/근거/참고 안내 표시.
- `error`: 한국어 오류 메시지 표시, 입력 유지, 다시 시도 가능.
- 새 요청 시작 시 이전 오류를 지운다. 새 요청이 실패하면 이전 결과를 현재 분석 결과로 오인하지 않도록 숨기거나 “이전 결과”임을 분명하게 한다.

## 결과 표시
- API 결과 키: `sentiment`, `confidence`, `reason`.
- 라벨은 `positive|negative|neutral`만 허용. 화면 표기: 긍정/부정/중립.
- 신뢰도는 0~100 정수 백분율이며, 숫자와 시각 막대를 함께 제공한다. “모델 추정치 · 참고용”을 인접 표시한다.
- 근거는 1~2개의 짧은 한국어 문장으로 표시한다. 원문을 그대로 길게 반복하지 않도록 한다.
- AI는 심리/의학 진단을 내리거나 특정 인물의 내면을 확정적으로 단정하지 않는다.

## 오류 문구
- 입력 누락: “분석할 문장을 입력해 주세요.”
- 길이 초과: “입력은 2,000자 이내로 작성해 주세요.”
- 일시적 서버/API 오류: “분석을 완료하지 못했어요. 잠시 후 다시 시도해 주세요.”
- 잘못된 응답: “분석 결과를 읽지 못했어요. 다시 시도해 주세요.”
- 구체적인 공급자 오류, 토큰, 키, 스택 추적은 브라우저에 노출하지 않는다.

# 06. 검증, 배포 및 완료 기준

## 기능 검증 체크리스트
- [ ] 정상 한국어 문장을 제출하면 긍정/부정/중립 중 하나와 근거 및 0~100% 값이 표시된다.
- [ ] 공백 입력은 네트워크 요청 없이 안내되고 입력 영역에 오류가 연결된다.
- [ ] 2,001자 입력은 제출이 막히고 길이 안내가 표시된다. 글자 수는 이모지/한글에서도 서버와 일치한다.
- [ ] 분석 중 버튼이 중복 제출을 막고 진행 상태를 알린다.
- [ ] API 키 미설정/공급자 실패/시간 초과/잘못된 응답에서 앱이 멈추지 않고 안전한 오류를 표시한다.
- [ ] 오류 후 입력을 수정해 재시도할 수 있다. 오래된 결과와 새 분석 상태를 혼동하지 않는다.

## 접근성 및 시각 검증
- [ ] 데스크톱과 360px 폭의 모바일에서 제목/입력/버튼/결과가 겹치거나 잘리지 않는다.
- [ ] 키보드만으로 입력, 제출, 오류 해결, 결과 확인이 가능하며 포커스가 눈에 보인다.
- [ ] 스크린리더에서 레이블, 버튼, 진행 상태, 결과 갱신이 이해된다.
- [ ] 색상 외에도 긍정/부정/중립 텍스트를 표시한다. 모션 감소 설정에서 장식 애니메이션이 중지된다.
- [ ] 첨부 참조의 검정/흰색/라임 대비와 대형 타이포그래피 방향을 따르되 가독성과 입력 사용성을 우선한다.

## 보안/개인정보 검증
- [ ] 브라우저 개발자 도구의 소스/네트워크 응답에 API 키가 없다.
- [ ] 저장소에 실제 키가 없고 `.env*` 비밀 파일이 추적되지 않는다.
- [ ] 서버 응답에 공급자 오류 전문이나 스택 추적이 없다.
- [ ] 텍스트 원문이 DB나 로그에 기록되지 않는다.
- [ ] UI에서 AI 제공자 전송 사실과 결과의 참고용 성격을 알린다.

## 배포 확인
- [ ] README의 환경변수/실행 절차만으로 새 개발자가 로컬 구동할 수 있다.
- [ ] Vercel Preview에서 정적 페이지와 `/api/analyze`가 모두 동작한다.
- [ ] Production 환경변수 범위와 배포 상태를 확인한다.
- [ ] 배포 후 모바일/데스크톱 핵심 흐름을 다시 점검한다.

## 최종 완료 보고 형식
구현 에이전트는 완료 시 변경 파일, 실행한 검증 및 결과, 실행하지 못한 검증과 사유, 필요한 환경변수/배포 후 조치를 간단히 보고한다. 검증하지 않은 항목을 통과로 표시하지 않는다.
